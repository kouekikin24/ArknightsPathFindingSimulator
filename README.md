# 明日方舟寻路模拟器

这是一个 Java 21 的逐帧寻路模拟核心，以及与核心解耦的 Swing 桌面界面。它用于审计和复刻单位在逻辑地图中的路线选择、转向、避障、碰撞、检查点、消失/出现与传送门行为。

模拟器固定为 `30 FPS`。连续状态统一保存和运算为 Java `float`（float32）；地图位置的单位是“格”，因此格 `(0, 0)` 的中心是 `(0.5f, 0.5f)`。项目刻意保留确定性的遍历顺序和逐帧轨迹，便于将录像或导出的 golden trace 与模拟结果逐帧比较。

## 坐标与判格

逻辑运动平面是 X-Y 平面，不使用渲染坐标或 Unity 的 Z 轴。

| 项目 | 规则 |
| --- | --- |
| 地图原点 | 左上角 |
| X 轴 | 向右增大 |
| Y 轴 | 向下增大 |
| 格 `(x, y)` 的中心 | `(x + 0.5f, y + 0.5f)` |
| 格 `(x, y)` 的覆盖范围 | `[x, x + 1) x [y, y + 1)` |
| 位置判格 | `floor(position.x)`、`floor(position.y)` |

判格直接对实际保存的 float 值取 `floor`，不使用 `roundToEven(position - 0.5f)`。因此整数格线属于正方向一侧的格：`x == 1f` 属于第 `1` 列；负坐标也没有奇偶偏置，例如 `x == -0.01f` 属于第 `-1` 列。float 的末位误差仍是输入状态的一部分，模型不会为了“接近格线”另行四舍五入。

## 帧模型与轨迹

权威推进入口是 `PathfindingSimulator.tick(long globalFrame)`：

- 第一帧可使用任意非负全局帧号；之后必须严格连续递增 `+1`。
- 避障只在 `globalFrame % 3 == 0` 时重算，其他两帧复用缓存。这个相位属于外部舞台帧，而不是某个单位私有的计数器。
- 无参 `tick()` 仍保留为已弃用的兼容包装；多单位或 UI 调用方应传入共享的 `globalFrame`。
- `FrameTrace.frame` 是该模拟器自己的从零开始审计序号，`FrameTrace.globalFrame` 是调用方传入的舞台帧号，两者刻意分开。
- `SimulationSession` 自己维护全局帧号；重建或重置场景时从零开始。

每个模拟器默认保留最近 `10_000` 帧的环形 `trace()`，按时间正序返回。较早轨迹被覆盖时可通过 `droppedTraceFrames()` 获取丢弃数；需要完整导出 golden trace 时，使用构造器提供的同步 `Consumer<FrameTrace>` 监听器，而不是依赖内存中的有限缓存。

## 已确认并实现的规则

- 使用反向 SPFA 生成到目标格的路径图；邻接顺序固定为上、右、下、左，且只在严格更短时松弛。寻路代价归属为“进入当前格”的代价。
- `nextNode` 按从下到上、从左到右的顺序原地平整化。改造 Bresenham 的完整窄带检查是已确认的专栏规则：当路径任一轴跨度为一格时，检查整个 `2 x N` 或 `N x 2` 窄带，不能以通用 Bresenham 走线替代。
- 避障对周围 8 格累计得到的向量 `a` 先归一化，再减去其在给定方向上的投影；当前格不可通行时，指向最近可通行格的向量也先归一化。避障每三帧按外部全局相位更新，即使单位绑定、等待或在地图外也不漏掉该相位帧；已消失或已完成单位不更新。
- 不吸附到中间节点、检查点或终点。移动始终经由惯性积分和碰撞修正；检查点/终点只按半径完成。
- 地图外出生会继续朝地图内部移动，但不会因此完成 MOVE/PATROL_MOVE 检查点。地图内无法到达当前移动检查点时进入 `BLOCKED`，只记录一次 `blocked unreachable MOVE`，不跳过检查点。
- 碰撞按格边扫掠处理：撞墙会清除整帧法向位移和惯性速度、保留切向滑动；同时跨越两条边且对角目标被阻挡时同时清除 X、Y，不做镜面反射或推进到墙边。
- 对地面单位，箱子、坑和特殊障碍使用高寻路代价并进入同一套 8 邻格避障计算。坑的寻路代价为 `1_000_000`，不是本轮改成“地面不可通行、飞行可通行”的语义。
- 飞行单位完全忽略地图内的箱子、坑、墙和自定义地形障碍：寻路统一按普通格代价，平整化不被地形阻断，避障恒为零，DDA 碰撞也不移除位移或惯性；地图边界仍是场景边界。
- 传送门（`APPEAR_AT_POS`）改变位置但完整保留进入时的惯性速度方向与大小。
- `DISAPPEAR` 后必须在下一个 MOVE/PATROL_MOVE 或路线结束前出现 `APPEAR_AT_POS`；非法路线在 `Route` 构造时以检查点索引报错。
- 巡逻回环采用已确认的专栏规则，而非通用巡逻约定：最后一个 `PATROL_MOVE` 的目标与首个检查点目标不同时，光标回到首个检查点；否则向终点继续。
- `Vec2f.normalized()` 与 `clampMagnitude()` 对齐 Unity `Vector2` 的近零阈值、平方比较和运算顺序。

## 目录

```text
src/main/                  模拟器源码，不依赖 UI
src/test/                  可执行的回归测试
src/ui/                    独立的 Swing 桌面界面
out/                       编译产物，运行脚本会自动重建，不提交到 Git
run-tests.cmd              Windows 批处理测试入口
run-tests.ps1              PowerShell 测试入口
run-ui.cmd                 Windows 批处理 UI 入口
run-ui.ps1                 PowerShell UI 入口
```

源码和测试均使用默认包，因此 `src/main` 与 `src/test` 下不再有额外的 Java 包目录。

## 桌面 UI

桌面界面位于 `src/ui`，通过 `SimulationSession` 单向调用模拟核心：核心不引用 Swing、Java2D 或任何界面类。界面可编辑地图地块、起点、终点和移动检查点，并显示路线图、单位位置、速度、避障、下一节点和检查点切换。

```bat
run-ui.cmd
```

```powershell
powershell -ExecutionPolicy Bypass -File .\run-ui.ps1
```

界面启动脚本只编译 `src/main` 与 `src/ui`；原有测试脚本仍只编译 `src/main` 与 `src/test`。

### 时间轴、轨迹与缩放

- 时间轴的逻辑单位是帧。`S[0]` 是尚未执行 tick 的出生状态；`S[n]` 严格等于从初始场景连续执行 global frame `0` 到 `n - 1` 后的状态，时间为 `n / 30 s`。
- 时间框接受整数帧（如 `16`）、精确分数 `16/30`，以及乘以 30 后恰为整数帧的有限秒数（如 `0.5`、`1.2`）。不能精确映射到整数帧的输入会报错并提示相邻合法帧，绝不取整、插值或使用浮点比较。
- 界面同时显示帧号和规范时间 `n / 30 s`。没有子帧插值，因为权威模拟只定义每个固定 `F32.DT = 1f / 30f` 状态；额外插值会伪造未执行过的状态。
- 红色实际轨迹只连接已生成连续帧的 `entityPosition`，即敌人圆形本体的位置。`cursorPosition` 仅用于调试十字。传送门 `APPEAR_AT_POS`、消失/出现或任意位置非连续跳变都会断开轨迹，绝不画跨地图直线。
- 地图初始按视口适应显示，使用滚动条查看放大后的区域。普通鼠标滚轮直接以鼠标下的世界坐标为锚点缩放；不需要 Ctrl。最大缩放保证单格边长至少覆盖视口长边，所有绘制与点击都使用同一坐标变换。
- 到达 BLOCKED 或 COMPLETED 终态后，终态之后的时间请求会被拒绝，不会伪造静止移动。

## 运行测试

需要 Java 21。任选一种方式运行：

```bat
run-tests.cmd
```

```powershell
powershell -ExecutionPolicy Bypass -File .\run-tests.ps1
```

两个脚本都会先清空并重建 `out`，再编译源码和测试。回归测试应覆盖坐标边界、SPFA 代价与平局顺序、完整窄带 Bresenham、平整化、无吸附惯性转向、全局三帧避障、地图外出生、不可达阻塞、扫掠碰撞、消失路线、巡逻回环、飞行模式以及轨迹环形缓存/监听器。

## 最小使用示例

```java
import java.util.List;

GridMap map = new GridMap(20, 12);
map.setRule(new TileCoord(8, 5), TileRule.impassable());

Route route = new Route(
        new Vec2f(0.5f, 0.5f),
        new Vec2f(18.5f, 5.5f),
        List.of(Checkpoint.move(new Vec2f(10.5f, 5.5f))),
        MovementMode.GROUND,
        true,
        true,
        false);

PathfindingSimulator simulator =
        new PathfindingSimulator(map, route, UnitConfig.normalGround(1f));
long globalFrame = 0L;
FrameTrace frame = simulator.tick(globalFrame++);
```

运行测试脚本后，可以执行演示程序查看两个检查点之间的惯性转弯：

```bat
java -cp out DemoMain
```

## 已知验证边界

- 本项目复刻的是已确认规则与当前参数的可审计模型，不宣称在缺少录屏/帧数据时已经逐帧证明与原作完全一致。
- 常量表中标为“当前复刻参数”的数值仍需用原作录像或能定位的专栏原文校准；它们不应被引用为原作公开定值。
- 碰撞、避障、浮点边界和检查点切换的最终保真度需要逐帧 golden trace 验证，尤其是高速度、多格跨越、复杂障碍与特殊单位配置。
- 模拟范围是逻辑寻路和运动，不包含 Unity 渲染、动画、网络同步、完整战斗系统或所有尚未公开/定位的特殊机制。
